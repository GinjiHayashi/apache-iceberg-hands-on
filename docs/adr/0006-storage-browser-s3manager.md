# 0006. ストレージの閲覧には s3manager を使う

- 日付: 2026-09-26
- 状態: 採用（ADR 0001 の「Web コンソールで閲覧する」を置き換える）

## 背景

要件では、S3 の中身を Web UI で確認できることを「あれば嬉しい」としていた。ADR 0001 では RustFS に付属するコンソール（:9001）を使う想定だった。
実際に使うと、ログインした直後に「セッションが切れた」と表示されて使えなかった。

調べると、RustFS 1.0.0 には既知の不具合がある。コンソールの内部パス（`/login`、`/session`）を S3 のバケット名として解釈し、アクセスを拒否してしまう（[rustfs/rustfs#8013](https://github.com/rustfs/rustfs/issues/8013)、2026-09-26 時点で未解決）。
サーバー側の STS やバケット一覧の取得は、同じ手順を API で再現すると正常に動いた。

## 検討した選択肢

- RustFS をプレビュー版（1.0.1-preview）に上げる — リリースノートに修正の記載がなく、プレビュー版に固定するのも避けたい
- ストレージを SeaweedFS に切り替える（ADR 0001 の代替策） — 影響が大きく、UI のためだけに切り替えるほどではない
- 軽量な S3 ブラウザ `cloudlena/s3manager` を追加する — 1 コンテナで数 MB、ログイン不要。閲覧、アップロード（フォルダごとも可）、削除ができる。Apache-2.0 で、活発に保守されている

## 決定

`cloudlena/s3manager:v0.10.0` を基盤のサービスに追加し、`127.0.0.1:8081` で公開する。RustFS のコンソールは使わない（ポートは不具合が直ったときのために残す）。

## 理由

- 追加するコンテナが小さく（メモリ上限 256MB。60MB のファイルをアップロードすると 64MB では足りなかった）、他の構成に影響しない
- ログインが不要で、ハンズオンの「ファイルの増え方を見る」という用途には十分

## 影響

- ドキュメントと教材の「RustFS のコンソール」を「S3 ブラウザ（http://localhost:8081 ）」に置き換えた
- s3manager は RustFS の管理者キーで接続するので、UI からすべてのファイルを削除できる。ローカル専用なので許容する
- RustFS の不具合が直ったら、コンソールに戻すかを見直す
