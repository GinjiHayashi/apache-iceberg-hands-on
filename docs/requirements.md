# 要件定義

> 状態: 確定（2026-09-26）

## 目的

ローカル環境で Apache Iceberg によるデータレイクハウスを構築し、Iceberg の主要機能を実際に操作して理解する（個人学習用）。

## 学習ゴール

すべて必須。

| # | 機能 | 実行エンジン |
| --- | --- | --- |
| a | テーブル作成と基本 CRUD（CREATE / INSERT / UPDATE / DELETE / MERGE） | Spark, Trino |
| b | スナップショットとタイムトラベル（過去時点のクエリ、ロールバック） | Spark, Trino |
| c | スキーマ進化（列の追加・削除・名前変更） | Spark, Trino |
| d | パーティション進化（隠しパーティション、パーティション仕様の変更） | Spark, Trino |
| e | エンジン間の相互運用（Spark と Trino で同じテーブルを読み書き） | Spark, Trino |
| f | Parquet から Iceberg への変換 | 設計で決定 |
| g | メンテナンス（Compaction、スナップショット失効、孤立ファイル削除、マニフェスト統合） | Spark と Trino の両方 |
| h | メタデータテーブルの参照（`$snapshots`、`$files` など） | Spark, Trino |

追加目標（任意）: テーブルフォーマット v3 へのアップグレード（各エンジンの対応状況を設計で確認してから）。

## 機能要件

### 構成要素

| 役割 | 採用 | 補足 |
| --- | --- | --- |
| クエリエンジン | Spark（PySpark）, Trino | 将来ほかのエンジンを追加できる構成にする |
| 軽量クライアント | PyIceberg | Jupyter コンテナ内で使う（[ADR 0004](adr/0004-pyiceberg-in-container.md)）。範囲はテーブル一覧・pandas/DuckDB への読み込み・簡単な追記 |
| カタログ | Apache Polaris | メタデータは PostgreSQL で永続化 |
| ストレージ | RustFS | S3 互換。データは永続化し、Web UI で閲覧する（[ADR 0001](adr/0001-object-storage-rustfs.md)、[ADR 0006](adr/0006-storage-browser-s3manager.md)） |

### ハンズオン教材

- Spark: 機能ごとの Jupyter ノートブック（JupyterLab で実行する）
- Trino: `.sql` ファイルをコンテナ内の Trino CLI で実行
- PyIceberg: Jupyter コンテナ内のノートブック

### 環境の起動と初期化

- `docker compose` で全サービスを起動する
- Polaris の初期設定（カタログ、プリンシパル、ロール、権限）は起動時に初期化コンテナが自動で作る。スクリプトには権限モデルを理解できるよう各手順の意味をコメントで書く
- 状態は再起動をまたいで残す。完全に初期化するときは `docker compose down -v` を使う

### データ

- 自分で DDL/DML を書いて作るデータ
- NYC タクシーの公開 Parquet データ（1か月分程度）。取得はスクリプトで自動化し、データファイルはコミットしない

## 非機能要件・制約

- 実行環境: Windows + WSL2（Ubuntu 22.04）、Docker Compose
- メモリ: WSL2 に割り当てられているのは 7.5GiB。合計 6GiB 以内を目安にする
  - 基本の起動単位は「基盤（ストレージ、カタログ、DB）＋エンジン1つ」。相互運用を検証するときだけ両エンジンを起動する
  - Compose の profile で起動するサービスを切り替え、各コンテナにメモリ上限を設定する
- Python の依存関係は uv で管理する（`pyproject.toml` と `uv.lock` をリポジトリに置く）。コンテナ内の追加パッケージと、ホストの開発ツールが対象。ホストへの Java のインストールは不要にする
- 費用: すべて無料で構成でき、アカウント登録も不要であること
- バージョン: コンテナイメージのタグ、Iceberg のランタイム jar などをすべて明示的に固定する。組み合わせは ADR に記録する
- テーブルフォーマット: v2 で統一する
- 認証情報: ローカル専用の固定値を使う。`.env.example` はコミットし、`.env` は gitignore する。実在の認証情報は含めない
- ドキュメント・ノートブックの説明・コードのコメントはすべて日本語で書く。Iceberg の用語は無理に訳さない

## スコープ外

- ローカル以外の環境（クラウドなど）での稼働
- 本番運用を想定したセキュリティ・可用性・性能

## 完了の定義

学習ゴール (a)〜(h) のそれぞれについて、ノートブックまたは SQL ファイルがあり、手順どおりに実行して動くこと。
